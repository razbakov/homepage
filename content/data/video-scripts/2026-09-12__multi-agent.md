## Point 1 — Give Every Agent a Job Description (0:20–1:10)

Here's where most people start wrong. They spin up an AI agent and say "be helpful." That's like hiring someone and telling them "just… be useful." It doesn't work with people. It doesn't work with AI either.

Every agent I build gets a configuration file — a proper job description. What's your role? What do you know? What are your skills? How do you communicate? Think of it as onboarding. You wouldn't throw a new hire into the deep end with no context. You'd give them the mission, the constraints, the team's language. Same thing here. Get specific. "You handle documentation." "You write tests." "You review architecture." The vaguer the role, the worse the output. Every time.

## Point 2 — Agent Management Is HR (1:10–2:10)

This was the realization that cracked it open for me. I wasn't writing prompts anymore. I was building an organization. Culture, roles, goals, onboarding, environment, performance reviews — the same six things you'd think about for any team. And the order matters. Before I wrote a single line of code, I defined the mission. OKRs. Documentation. A knowledge base with an index so agents could actually find things. Task breakdowns with clear success metrics — because if an agent doesn't know what "done" looks like, it just keeps going.

Once that foundation existed, the building phase was almost easy. The agents had context. They knew the mission. They knew the constraints. They proposed solutions I wouldn't have thought of on my own. But only because I'd done the boring work first — the planning, the docs, the structure. The unsexy stuff is the whole game.

## Point 3 — Talk Problems, Not Solutions (2:10–3:05)

Here's where people really get it wrong. They tell the agent what to build instead of what problem to solve. When you dictate the solution, you get exactly what you asked for — which is usually not what you needed.

I use something called Six Thinking Hats — a framework by Edward de Bono. Six perspectives. Facts. Gut feelings. Criticism. Praise. Alternatives. Process. I gave a talk about this years ago, long before I touched AI. Turns out it's the perfect vocabulary for giving feedback to agents. You don't need to be polite. You need to be clear. "The test fails on Y" — that's facts. "Something feels off" — that's intuition. "What if we tried the opposite?" — that's alternatives. The AI picks up on these shifts. It's weird how well it works.
