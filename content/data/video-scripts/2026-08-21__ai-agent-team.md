## Point 1 — The Cabinet (0:20–1:10)

Here's how I think about it. You wouldn't run a company alone. You'd hire a CTO, a head of content, a chief of staff. So that's exactly what I did — except they're AI agents running in terminal sessions.

Maya is my chief of staff. She triages my inbox, routes tasks, runs the daily review. Viktor handles code — PRs, architecture, the stuff I used to lose weekends to. Luna writes content. Marco turns messy ideas into structured plans. Sage coaches me on life balance. Kai manages relationships and follow-ups.

Six agents. Six clear domains. No overlap, no confusion. I just send a message on Telegram, and Maya figures out who handles it. The key insight? Agents need structure, not freedom. Each one has a detailed skill file — step-by-step, no ambiguity. Vague prompts give you vague results.

## Point 2 — Fire and Forget (1:10–2:10)

So what do I actually do all day? Four things. Strategic decisions — what to build, what to kill. Being the face — showing up, presenting. Building relationships. And validating ideas with real users. That's it. Everything else is delegated.

The pattern that makes this work — I call it the inbox pattern. One command. It creates an isolated workspace, writes the prompt, launches the agent in the background, and logs everything. I don't watch it run. I don't hover. I check results later with a single scrum command that reads all agent logs at once.

Fire and forget beats micromanagement every time. And here's what surprised me — giving agents names and personalities isn't just fun. It creates accountability. When Viktor owns code review, I know exactly where to look when something breaks.

## Point 3 — No Special Infrastructure (2:10–3:05)

Now you might think this requires some fancy custom platform. It doesn't. Claude Code for the brain. Markdown files for skills and context. Git worktrees for isolation — each agent works on its own branch without stepping on another. Tmux for parallel sessions. Notion for tracking. Telegram for input. That's the whole stack.

And the governance? I borrowed from Sociocracy 3.0. Clear domains — no agent overrides another's territory. Every task starts with a driver — the why. And agents deliver pull requests, not status updates. Everything is reviewable.

This isn't theoretical. I recorded a walkthrough from my Apple Vision Pro workspace — seven minutes showing the whole system live. And the skill files, the agent definitions, the routing — it's all open. You can build this yourself tonight.
